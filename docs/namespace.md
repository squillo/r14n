# The RLPS namespace — minted terms + graceful degradation

**Namespace URI:** `https://rlps.squillo.com/ns#` (constant [`RLPS_NS`] in the resolver's
`receipt` module). Minted under squillo.com control; a `w3id.org/rlps` alias is planned
**post-publication** (registering w3id before the counsel gate would be a public step). The URI
is an identifier first — receipts are valid whether or not it dereferences.

> **⚠ NOT LEGAL ADVICE.** Terms name *controls and receipt structures*, not legal conclusions.
> See `/docs/not-legal-advice.md`.

## Why an RLPS-owned namespace (spec §8 / an internal design memo must-fix #6)

W3C DPV does not (yet) define recording-operation terms at the granularity RLPS needs
(`AudioRecording` vs `VoiceRecording` matters — voice is a biometric-adjacent special-category
gate). We proposed adjacency to DPVCG is *future* work; interop MUST NOT be contingent on
external adoption. So RLPS mints its own terms and **degrades gracefully**:

- The receipt `@context` is **self-contained**: `@vocab` = the RLPS namespace, so every bare
  key resolves to an RLPS URI with no external fetch and no DPVCG dependency.
- Established DPV terms are used **only where DPV already defines them**:
  `dpv:DataSubject`, `dpv:DataController`, `dpv:hasJurisdiction`.
- If DPVCG later adopts recording terms, packs/receipts MAY emit both (`rlps:` term +
  `dpv:` equivalent); the RLPS term remains canonical for RLPS conformance.

## Minted terms (v0.1)

| Term | Kind | Meaning |
|---|---|---|
| `rlps:ControlDecisionReceipt` | class | The RLPS decision receipt document (27560-structured). |
| `rlps:RegulatedActivity` | class | The (domain × subject) activity a decision governs. |
| `rlps:ControlDecision` | event type | The resolver decision event (`event_state` = verdict). |
| `rlps:AiDisclosure` | event type | An EU-AI-Act-Art.-50 disclosure event (`event_state` = method). |
| `rlps:AudioRecording` | processing op | Capturing meeting/session audio. |
| `rlps:VideoRecording` | processing op | Capturing meeting/session video. |
| `rlps:VoiceRecording` | processing op | Capturing voice specifically (biometric-adjacent; distinct GDPR Art. 9 exposure — SEPARATE from generic audio). |

Term-minting rules: lowerCamelCase for properties, UpperCamelCase for classes/operations;
a term is added here + referenced from the spec before first use in a shipped receipt;
terms are never removed, only deprecated (receipts are long-lived audit evidence).

## Receipt serializations that use this namespace

- **ISO/IEC TS 27560 + DPV JSON-LD** — `receipt::dpv_27560()` (the native form).
- **Kantara CR v1.1 shim** — `receipt::kantara_cr_v1_1()` (flat; RLPS provenance rides in the
  `rlps` extension block).
- Example (EU AI Act Art. 50, fixed timestamps, reproducible):
  [`/docs/examples/receipt-ai-act-50.json`](examples/receipt-ai-act-50.json), regenerated by
  `cargo run --example ai_act_50` in `/resolver`.
